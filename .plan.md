# Phase 6 Implementation Plan (`@repo/cli`)

## 1. Scope and Command Matrix
- Define initial high-value commands: `auth`, `accounts`, `categories`, `transactions`, `transfers`, `reports`, `credit-cards`, `statement-payments`.
- For each command, specify:
- input flags/options
- output shape
- supported mode: `local`, `remote`, or both

## 2. CLI Architecture Baseline
- Keep package boundaries aligned with `.codex`:
- CLI orchestrates use, does not host heavy business rules
- business rules remain in `@repo/domain`
- Organize `packages/cli/src` into:
- `commands/`
- `services/`
- `adapters/`
- `formatters/`
- `config/`

## 3. Runtime Mode Resolution (`local` vs `remote`)
- Implement a single mode resolver with env + flag override (`--mode local|remote`).
- `local` mode:
- execute via `@repo/database` repositories/use-cases
- `remote` mode:
- execute via API calls using `@repo/shared` contracts

## 4. Composition Root and Context
- Build one composition root for command execution lifecycle.
- Wire shared dependencies once per run:
- logger
- clock/time provider
- auth/session provider
- mode-specific adapter set (local or remote)

## 5. Remote Auth and Session
- Implement:
- `auth login`
- `auth refresh`
- `auth logout`
- `auth me`
- Persist CLI session/token in a simple local file, scoped by environment.

## 6. First Vertical Slice (End-to-End)
- Implement one complete flow in both modes:
- `transactions create`
- `transactions list`
- Validate end-to-end:
- argument parsing
- mode switching
- response mapping
- output formatting

## 7. Module Expansion Strategy
- Expand commands in this order:
1. `accounts`, `categories`, `payees`
2. `transfers`, `recurring-transactions`
3. credit-card flows and statement payments
- Preserve critical financial rule:
- credit-card purchases do not create direct `transactions`
- statement payments create the real financial `transaction`

## 8. Output and Error Standards
- Default output: human-readable terminal format.
- Automation output: `--json`.
- Standardize error mapping:
- validation/domain/internal errors
- stable CLI exit codes

## 9. Testing Strategy
- Unit tests:
- argument parsers
- formatters
- mode resolver
- auth/session store
- Integration tests (`local`):
- SQLite test DB flows
- Integration tests (`remote`):
- API test server with seeded data
- Contract checks:
- CLI request/response payloads aligned with `@repo/shared` schemas

## 10. Scripts and Documentation
- Add package scripts in `@repo/cli`:
- `dev`
- `typecheck`
- `build`
- `test`
- Document:
- command reference
- local vs remote behavior
- required env vars
- usage examples

## 11. Delivery Milestones
1. **M1**: CLI skeleton, mode resolver, auth/session, first vertical slice.
2. **M2**: Core finance commands (`accounts`, `categories`, `transactions`, `transfers`).
3. **M3**: Credit-card operational flows, statement payments, reports.
4. **M4**: Hardening (tests, docs, stable errors/exit codes, DX polish).

## 12. Acceptance Criteria
- `@repo/cli` passes `typecheck` and `build` under workspace standards.
- Covered commands behave consistently in `local` and `remote` modes.
- Contracts remain aligned with `@repo/shared`.
- Business rules remain in `@repo/domain`.
- Automated unit and integration tests pass.
